# 3D 模型与场景验收标准（v1.0）

> 2026-08-29 调研沉淀。依据三源交叉：工业 game-ready 资产标准（alpha3d / ActionVFX / Wavect 2026）、
> AI 生成 3D 学术评估基准（MATE-3D / Eval3D, CVPR 2025）、关卡美术可读性理论（The Level Design Book / GameDeveloper / Blendo）。
> 与 UI 拆层素材三关（烘焙关/9-slice 关/对比关）同构：**自动化查硬伤（gate）+ 人眼评软分**。

## 核心调研结论

1. **"Game-ready 是验收结果，不是生成器标签"**（Wavect 2026）——AI 生成模型导入成功 ≠ 生产验收，必须在目标引擎实机验证。
2. **全自动打分不可靠**：MATE-3D（1280 个网格、10.7 万条人评标注）实测 CLIPScore 与人评相关性仅 PLCC≈0.54，Aesthetic Score≈0.23——所以游戏工业用 checklist gate 而非连续分数，人眼保留终审权。
3. 学术界共识的四维 = **对齐度（text-3D alignment）/ 几何 / 纹理 / 整体**（MATE-3D、Eval3D 均按此切分），可映射为人眼评审的四个打分项。
4. 场景美术的可量化抓手是**明度层级**（Value Hierarchy）：截图灰度化后看前/中/后景三段明度分布（The Level Design Book 判例：PS 色块化评估法）。

## 一、3D 模型三关

### 关 1 · 技术合规关（一票否决，自动化 → `Tools/AI Town/Validate Model Health`）

| 检查项 | 标准 | 本项目实锤判例 |
|--------|------|----------------|
| 单位 | 米制；厘米 FBX 必须实测反推 scale 后**硬编码进 manifest** | 厘米 FBX renderer.bounds 大 100 倍，运行时测不可靠（2026-08-28） |
| 轴向 | Y-up；Z-up FBX 导入后 rotX=270 转正 | 灯笼柱/酒旗均 Z-up，轴心在几何中心 |
| 原点 | 轴心在几何中心或底部需明确；y=半高×scale 落地 | 树 y=3.8225 同构 |
| 材质 | URP shader；禁 null / error(magenta) / Standard 内嵌白模 | Rodin FBX 内嵌材质 URP 下渲染纯白 → 必须指派 .mat（Mat_FlagRed 判例） |
| 面数 | 单件 ≤ 3 万三角（lint 阈值）；特写核心资产另立 brief | 资产库道具普遍 1-2 万 |
| 尺度 | 渲染包围盒高度 0.05~20m 之外=异常（漂浮/巨人） | — |
| 碰撞体 | 玩家可交互/可撞物必须有 Collider | — |

### 关 2 · 几何轮廓关（人眼）

- 剪影可读：眯眼看轮廓能否辨认"是什么"。
- 无破洞 / 自相交 / 漂浮零件 / 法线翻转（Wavect AI 3D 验收流程：先查无纹理网格）。
- texel density 一致：贴图像素密度均匀，否则远处糊、近处烂（棋盘格材质直查）。

### 关 3 · 风格统一关（人眼）

- 色域落在民国配色内（对照 UiTheme：墨/宣纸/朱红/铜金）。
- 材质语言统一：树=墨绿 Lit（Mat_ScholarTree）、灯柱=深铁灰；新树种务必带 material 字段（2026-08-28 判例）。
- 落地后联检：摆放合规走 `Validate Placement`（禁区/间距/白名单）。

## 二、场景四查

### 查 1 · 明度层级（半自动 → `Tools/AI Town/Validate Scene Luminance`）

- 原理：灰度三段——**前景阴影框景 / 中景中间调 / 背景高光（天空）**。
- 参考带（lint 阈值，可调）：shadow 15~45% · mid 30~65% · highlight 8~40%；平均亮度 0.3~0.65。
- 采样法：主相机渲到 RenderTexture 读像素统计，规避截图陈旧帧坑。
- 判例：黄昏校准（雾 28~85m、天空盒暖染、灯 5.5 强度）就是手动做过一轮的三段平衡。

### 查 2 · 可读性 / 动线（人眼 + 既有规则）

- choice density：一个空间的主出口/兴趣点 ≤3（Blendo：5 个出口=玩家过载）。
- 路网连通：主街/巷道连贯，新建筑自动接路（RoadBuilder）；静态路网只改 `AiTownMinguoAtmosphere.BuildRoadNetwork` segments。
- 空间逻辑：每个区域"命名/脉络/规则/时间"四要素（scene-zoning skill）。

### 查 3 · 构图与焦点（人眼）

- **最重要的物体打亮，其余压暗**，不可倒置（GameDeveloper composition 判例）。
- 剪影强调：主视觉（洋楼/牌坊）轮廓在天空盒上可读。
- 光/色引导动线：暖点光源（灯柱）指路，路面包裹视线。
- 仓库法（Charles Boury）：把所有道具按类网格摆一排截图，审 palette/剪影/LOD 一致性——验收道具批次的土办法。

### 查 4 · 性能硬线（可自动化，UCDC 档位）

| 档位 | DrawCalls | Tris | 说明 |
|------|-----------|------|------|
| 满分 | <200 | <50K | UCDC 性能 5 分线 |
| 合格 | <300 | <100K | 4 分线 |
| 警戒 | >500 | >300K | 2 分线 |

- 场景 Tris 可由模型体检逐件累计得近似值；DrawCalls 需 Play 模式 Statistics 窗口人工读。

## 三、与 UCDC 评分维度对照

| UCDC 维度 | 分值 | 本标准对应 |
|-----------|------|-----------|
| 美术表现 | 5 | 模型关 2/3 + 场景查 1/2/3（风格统一/材质光照/协调） |
| 性能表现 | 5 | 场景查 4（DC/Tris 档位） |
| 团结引擎深度使用 | 15 | URP 材质合规（关 1）+ 民国灯光氛围（查 1/3） |

## 四、工具对照速查

| 命令（Tools/AI Town/） | 覆盖 |
|------------------------|------|
| Validate Model Health | 关 1 + 查 4 部分：全场景根遍历（含 inactive；跳过名单豁免玩家/相机/系统件），材质/面数/高度/白模逐件查 + 碰撞体/投影/Static 提示（限道具/建筑件，Static 汇总行）+ 场景 Tris 总量汇总 |
| Validate Scene Luminance | 查 1 明度三段采样（主相机当前朝向，单视角） |
| Add Prop Colliders | 关 1 碰撞体落地：幂等补 BoxCollider（mesh.bounds 世界盒+identity 子物体，按类型收窄：树 0.35/旗灯 0.4/椅车 0.85）；Step 1 重摆自动带上 |
| Mark Static Geometry | 查 4 性能落地：_Props/_Buildings/_Roads/_River/Ground 全节点批量勾满 StaticEditorFlags（NPC/粒子/系统件排除），幂等；建筑重烘后重跑补回 |
| Validate Placement / Validate And Fix | 摆放禁区/间距/白名单（既有） |

### 已知未自动化项（人工或后续迭代）

- **明度采样视角单一**：当前只采主相机编辑态朝向；玩家实际动线采样（出生点/广场中心多向）待加。
- **DrawCalls 实测**：需 Play 模式 Statistics 窗口人工读。
- **UV/法线自动化**：噪声大，归关 2 人眼审（棋盘格/无纹理网格直查）。
